# 닉네임 회원가입·관리자 승인 기능 — 보관용 개발 브랜치

이 기능은 `feature/access-approval-draft` 브랜치에만 있습니다. **현재 운영 사이트와 별도 미리보기 프로젝트에 적용하지 않았으며, Supabase 프로젝트도 생성하거나 수정하지 않았습니다.** 본 브랜치를 Vercel에 자동 배포하도록 연결하지 마세요.

## 구현 범위

- `/login.html`: 닉네임(한글/영문/숫자/하이픈/밑줄, 2~20자) + 비밀번호(10~128자) 회원가입·로그인.
- 가입 시 `pending`으로 저장; 승인 전에는 로그인 불가.
- `/admin.html`: 관리자만 가입자 닉네임, 가입 시각, 승인 상태, 최근 로그인 시각, 로그인 횟수를 확인하고 승인/거절/차단/대기 상태를 선택.
- `/api/access`: 서버가 비밀번호 scrypt 해시를 검증하고 7일 만료, HttpOnly+Secure+SameSite=Strict 쿠키에 무작위 세션 토큰을 저장. DB에는 토큰의 SHA-256 해시만 저장.
- `proxy.js` + `vercel.json`: 미승인·미로그인 이용자의 계산기 HTML과 CSS 파일에 대한 직접 URL 요청도 서버에서 차단. 매 요청에 Supabase 회원 상태를 다시 확인하며, 차단된 계정의 세션은 효력이 없어짐.
- DB 속도/호출 비용이 적지 않을 수 있으므로 실제 배포 전 테스트 필요. 원래 계산기 파일은 이 브랜치에서도 수정하지 않음.
- 회원 비밀번호 원문, Supabase 비밀키는 화면이나 GitHub에 저장하지 않음.
- 가입/로그인 시도: IP별 DB 원자적 횟수 제한(가입 10분에 5회, 로그인 10분에 15회).

## 실제 적용할 때만 진행할 설정

1. 본 브랜치 코드를 검토하고 `npm install`, `npm run test:access`로 테스트한 뒤, 실제 Vercel 배포에서 로그인과 HTML/CSS 직접 접근 차단을 종단 간 검증.
2. 무료 Supabase 프로젝트를 연결하고, `supabase/sql/access-control.sql`을 SQL Editor에서 실행. **아직 실행하지 않음.** SQL 파일은 적용 전 검토와 권한 확인 필요.
3. Vercel의 서버 환경변수 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`를 설정. **실제 값은 저장소에 입력하지 말 것.** `sb_secret_...` 신형 Secret API key를 서버에만 등록.
4. 먼저 관리자용 닉네임/비밀번호로 `/login.html`에서 회원가입. Supabase SQL Editor에서 `access_members` 테이블의 해당 닉네임을 검토하고, 그 회원의 `role='admin'`, `status='approved'`, `approved_at=now()`만 수동 변경. 관리자 권한을 부여하는 공개 API는 구현하지 않음.
5. 실제 다른 사용자를 가입시켜 `pending` 상태에서 `/calculator.html`, `/core.html`, `/awakening.html`로 직접 접근 시 차단되는지 확인. 관리자의 승인 후 정상 접근, 승인 취소·차단 즉시 재접근 거절 확인.
6. **별도의 사용 승인 후에만** 브랜치 병합과 운영 사이트 배포를 진행.

## 보안/운영 주의

- 이 기능은 **배포한 웹사이트**의 접속을 제어합니다. 현재 GitHub 저장소가 공개라면 계산기 HTML/JS 소스 자체는 별도로 열람할 수 있습니다. 코드를 비공개로 만들려면 GitHub 저장소 공개 여부 및 배포 전략을 따로 검토해야 합니다.
- 사람마다 다른 비밀번호를 쓰도록 해야 합니다. 닉네임만으로 실제 신원을 확인할 수는 없습니다.
- 이메일을 받지 않는 방식이므로 자동 비밀번호 찾기/재설정은 미구현입니다. 운영자가 별도 안전한 절차를 마련해야 합니다.
- 회원 목록은 최근 가입 500명까지만 표시합니다. 서비스 규모가 커지면 페이지네이션을 추가하세요.
- 회원가입/승인/로그인 상태 추적은 DB 저장; IP별 제한 기록이 일부 남습니다. 개인정보 고지와 보관기간 설정, rate-limit 데이터 정리 절차를 마련해야 합니다.
- 서버(함수 및 Middleware)와 Supabase가 모두 무료 사용 한도 내에 있어야 비용 0원을 유지할 수 있습니다. 호출량이 늘면 비용 또는 제한이 발생할 수 있습니다.
- 배포 전 Vercel의 Routing Middleware가 정적 자산을 보호하는지 실제 환경에서 반드시 검증하세요. 단순 화면 가림이나 클라이언트 측 로그인으로는 접근을 막을 수 없습니다.
